How the team box works

TEAM SANDBOX - this is the team's shared workspace on the team computer. Not your computer, not Marjus's computer.

This page explains, in plain words, what team.xseed.ing is, what it stores, who can see what, and how you can check each claim yourself. It is public on purpose, so that you - or an AI you trust - can read it before signing in.

What it is

The team box is a separate computer that belongs to the team (a PC with an RTX 3060, running xOS, a Linux system). It is not a member's computer and not the owner's work PC (BESNIK) or personal PC. It holds none of the owner's files or secrets. It reaches the owner's shared AI models only through one narrow, capped door on BESNIK: the team gateway, which only offers chat with shared models and start/stop within caps.

Signing in

The address is protected by Cloudflare Access: you sign in with your email (a one-time code). The app trusts that email only when the request arrives through the team box's own Cloudflare tunnel, and (when switched on) after checking Cloudflare's signed login token. Admins are the owner's email address(es), set in the box's configuration; everyone else is a team member.

Sandboxes

Each member gets a private sandbox and can create more. A sandbox is a git repository on the team box that starts from a clean template: a README, guardrail files for AI tools, and a tiny example. It never contains a copy of anyone's own files or of BESNIK's code. Only you and the admins can see your sandboxes, builds, chats and settings versions - the server checks this on every request, for the web pages, the API and git. Asking for someone else's sandbox gets the same answer as asking for one that does not exist. The one exception is the weekly team feed: every Tuesday at 14:00 it shows the team read-only copies of what you made (never your chats, never access to the sandbox itself).

AI builds

You describe a task; a shared model (through the team gateway, under your account's caps) works in your sandbox with a fixed set of tools: list, read, search, write, edit, run a test, list checkpoints, roll back, finish. Every accepted change is saved as a checkpoint (a git commit). One build per person at a time, and only a few on the whole box at once.

The jail. Every test - from the AI builder, from your pushes, or from "Run tests now" - runs inside bubblewrap on a throw-away copy of that one sandbox: no network at all, its own process space, a fake minimal /etc, no view of other sandboxes, the app, the box's data or any secret, a memory limit, a process limit, a file-size limit and a time limit. When the test ends, the copy is deleted.

The safety check (tripwire). If a test the AI builder wants to run contains a word that a test never needs (for example trying to switch namespaces, read other processes, reach the tunnel or the box's own data), it is not run. The AI is told the word, the line and why, and keeps working without it - the build never waits. An admin can "let it pass" for that exact file content.

Models & settings versions

You can chat with the models the owner shares with the team, start or stop them if they are startable, and save your own settings (system prompt, temperature, top_p, answer length, how much history to keep) as named versions under your profile. The Original version (the model's own settings) is always kept and can always be chosen. The gateway may lower values over a model's limits, and when it refuses something (for example a start over your caps) you see its reason word for word.

Bring your own AI tool

Every sandbox is also a git remote: https://team.xseed.ing/git/<your-id>/<sandbox>.git. You authenticate with a token you make on your profile page. It is shown once, stored only as a hash, and you can revoke it any time. A token reaches only its owner's sandboxes; admins can read every sandbox and cannot push to yours. Each sandbox contains CLAUDE.md, AGENTS.md, GEMINI.md, .cursorrules, .cursor/rules, .github/copilot-instructions.md and opencode.json. They tell AI tools that this is a team sandbox on a shared server, to stay inside the repository, never to probe or escape anything, and to refuse if asked. Those files are guidance only. A tool can ignore them. The protection is the server's jail, the token check and admin-only promote. Every push that changes your main branch runs your tests in the jail. The push is then listed under AI builds, where an admin can review it.

Promote (admins only)

Only admins can promote a build into the shared team project. They review its changes (the exact diff a promote would add), its tests and its summary first. The server enforces this on every request, whatever the page shows. A member can reject their own builds only.

Caps

The owner decides how much model memory and how many running models each account may use. The team gateway on BESNIK enforces this. The team box cannot change it.

Team feed (every Tuesday 14:00)

Every Tuesday at 2 pm, team box time (America/Chicago unless the box's configuration says otherwise), everything members made before that moment and not yet published becomes visible to the whole team in Team feed:

  • finished builds (AI builds and pushes from your own AI tool): the task, the summary, the changed files, the diff and the test results;
  • commits on your sandboxes' main branch (the list and the changes);
  • new sandboxes you made (their file list; your automatic "my-sandbox" is not announced);
  • the settings versions you saved for a model (name and settings, including the system prompt).

Everyone on the team can comment on each item and react with an emoji. Before the Tuesday publish, your work is visible only to you and the admins, exactly as described above. A build that is still running waits for the next Tuesday. What is published is a read-only copy made at 14:00 and kept by the team feed. It does not give anyone access to your sandbox, your builds page or your git remote: those still answer "no such ..." / 403 to everyone but you and the admins. Your chats are never published. The Team feed page lists "your work that goes out next time", so you can see in advance exactly what will be shown.

The publish runs inside the app (checked every minute). If the team box was off at 14:00 it publishes as soon as it is back, and that week is marked "published late". Each Tuesday is recorded and published once, even if the check runs twice. Admins can "publish now" for testing; that is shown as an "Early publish", and the next Tuesday then publishes only what is new.

Home feed

The home page has the team's feed: anyone can post text and attach files. Everyone on the team sees the home feed and can comment and react with an emoji. You can edit and delete your own posts; admins can delete any post. Deleting a post deletes its files.

  • Allowed files: pictures (png, jpg, gif, webp), videos (mp4, mov, webm), notes (txt, md), spreadsheets (csv, xlsx, ods, xls), PDFs and documents (docx, odt, pptx, doc, rtf). Other types are refused. The start of the file must match its type: a web page renamed to .png is refused.
  • Size caps (set in the box's configuration; defaults): 95 MB per file (Cloudflare refuses bigger uploads) and 1000 MB in total per member.
  • Storage: files are kept outside the website's folders under random names, never the name you gave them.
  • Showing them: only pictures and videos are shown inline. Everything else is a download. Notes and spreadsheets get a "Preview": the text, or the first rows of the sheet as a table of plain text - nothing in them is run or formatted. HTML and SVG files are accepted only as downloads (application/octet-stream, Content-Disposition: attachment): they can never open as a page on this site. Every file is sent with X-Content-Type-Options: nosniff and a sandboxing Content-Security-Policy.

Messages, calls, video calls and the monitoring notice - not live yet

Planned design: the content is encrypted at rest to the owner's AI's (Lumi's) key and can only be decrypted on BESNIK. Members read their own conversations. Monitoring is done by an AI first, and any concern is checked by a third-party AI before it reaches a human. Before first use you must accept this notice from the owner:

What is stored today, and who can see it

  • Your profile (email, display name, language, tour progress), your sandboxes, builds and their transcripts, your chats with the AIs and your settings versions. All of this is on the team box's disk, under your member folder. You and the admins (and whoever operates the machine) can read it. It is not encrypted at rest yet.
  • Home feed posts, their files, comments and reactions (visible to every team member), and the team feed's read-only copies of published work. Also not encrypted at rest.
  • Your git tokens: only a hash of each one.
  • On BESNIK, the team gateway logs usage numbers per account (model, tokens, seconds), not the text of your chats.
